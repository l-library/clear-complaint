# 清诉前端功能与页面清单（补充版）

本文档列出前端需要实现的功能、用户操作、对应页面，以及建议前端发送和后端返回的数据，供 A 编写 `API.md` 时参考。

说明：

- 本项目为比赛模拟演示系统，不需要真实注册登录；
- 所有用户均为模拟患者，数据为演示数据；
- 文中数据项是功能建议，不代替 A 在 `API.md` 中确定的最终字段名；
- 当前已经完成前端 Mock 主流程，真实后端和 AgentArts 尚未接入。

## 页面总览

1. 首页
2. 个人信息确认页
3. 咨询输入页
4. 澄清追问页
5. 分诊结果页
6. 纠偏与评估页
7. 健康档案页

## 推荐流程

```text
首页
  ↓ 开始模拟问诊
个人信息确认页（预设演示患者，可修改）
  ↓ 确认信息，创建匿名会话
咨询输入页
  ↓ 提交主诉
澄清追问页
  ↓ 补充信息，可能多轮追问
分诊结果页
  ├─ 保存本次咨询
  ├─ 查看健康档案
  └─ 查看纠偏与评估
          ↓
       重新演示
```

## 功能清单

### 1. 首页

展示清诉的产品定位、演示患者和主要能力。

用户可以点击“开始模拟问诊”进入个人信息确认或咨询流程，也可以查看健康档案。

对应页面：首页。

**建议前端发送**

- 首次打开页面不强制请求后端；
- 如果已有演示患者或上次会话，可以发送对应 ID。

**建议后端返回**

- 演示患者基础信息；
- 历史问诊数量；
- 下次随访时间。

接口不可用时，首页使用内置演示数据，不能影响用户进入 Mock 流程。

### 2. 确认个人信息

首次进入问诊前，用户确认或修改基础信息：姓名、年龄、性别、既往病史、长期用药。

页面先填入演示患者信息，用户无需从空表单开始填写。点击“确认信息并继续”后进入咨询输入页。

对应页面：个人信息确认页。

**建议前端发送**

- 姓名；
- 年龄；
- 性别；
- 既往病史；
- 长期用药。

**建议后端返回**

- 匿名患者 ID；
- 本次会话 ID；
- 保存成功状态。

后续咨询请求使用后端返回的会话 ID。该页面不要求真实注册或登录。

### 3. 输入主诉

用户输入自己的不适或健康问题，并提交给 Agent。

输入为空时给出提示；提交后进入澄清追问。

对应页面：咨询输入页。

**建议前端发送**

- 会话 ID；
- 用户输入的主诉原文。

**建议后端返回**

- 是否需要继续澄清；
- 澄清追问问题列表；
- 如果无需澄清，返回可以进入分诊结果的状态。

### 4. 展示澄清问题

页面展示 Agent 发现的信息缺失和风险表达，例如用户把头晕直接归因于没睡好，或想自行停用降压药。

每个问题下可以给出可选项，例如“是 / 否 / 不确定”，同时允许用户自由填写。

对应页面：澄清追问页。

**建议前端发送**

- 会话 ID。

**建议后端返回**

- 追问问题列表；
- 每个问题的展示文案；
- 问题类型：信息缺失或风险表达；
- 可选项；
- 是否允许自由填写。

### 5. 提交补充信息

用户补充症状持续时间、最近血压、伴随症状和用药情况。

提交后，如果信息已经足够，进入分诊结果页；如果仍不足，页面继续展示新一轮追问。

对应页面：澄清追问页。

**建议前端发送**

- 会话 ID；
- 本轮追问的回答内容。

**建议后端返回**

- 是否还需要继续追问；
- 如果仍需追问，返回下一轮问题；
- 如果信息足够，返回可以进入分诊结果的状态。

问题列表由后端和 Agent 决定，前端不固定为四个问题。

### 6. 展示分诊结果

页面展示就医层级、建议科室、可能相关情况、每条情况的证据来源以及就医前准备。

页面提供三个操作：

- 保存本次咨询结果；
- 查看健康档案；
- 查看纠偏与评估详情。

对应页面：分诊结果页。

**建议前端发送**

- 会话 ID。

**建议后端返回**

- 就医层级；
- 建议科室；
- 可能相关情况列表；
- 每条情况的说明；
- 每条情况的证据标题、引用内容和来源；
- 就医前准备事项；
- 是否允许保存；
- 是否创建随访。

### 7. 展示纠偏结果

页面展示原始回答、纠偏后的回答、被识别的风险，以及纠偏前后的效果指标。

用户从分诊结果页点击“查看纠偏评估详情”进入本页；本页同时提供“重新演示”按钮。

对应页面：纠偏与评估页。

**建议前端发送**

- 会话 ID。

**建议后端返回**

- Agent 是否判断需要纠偏；
- 原始回答，若接口提供；
- 纠偏后的回答；
- 识别到的风险点列表；
- 每个风险点的类型与说明；
- 实际使用的纠偏策略，若接口提供；
- 纠偏前后的效果指标；
- 指标所属范围：本轮运行、实验汇总或 Mock。

如果后端不返回原始回答或内部策略，前端只展示可获得的最终纠偏说明，不自行补造 AI 的内部过程。

实验循环属于阶段一研究，不在前端运行，也不要求用户等待实验完成。

### 8. 咨询结果保存

用户在分诊结果页点击“保存本次咨询结果”，把本次问诊的结构化结果存入健康档案。

保存成功后给出提示，并提供“查看健康档案”跳转。

对应页面：分诊结果页。

**建议前端发送**

- 会话 ID。

**建议后端返回**

- 保存成功状态；
- 本次健康档案记录 ID。

建议由后端根据会话 ID 保存已有的结构化结果，前端不重新提交整份分诊和纠偏结果，避免前端篡改或组装出与 Agent 输出不一致的数据。

### 9. 查看健康档案

页面展示患者基本信息、近期血压趋势、历史问诊记录和下一次随访时间。

历史问诊记录支持点击某一条，查看当时的完整问诊、分诊和纠偏详情。

页面提供“录入血压”入口，用户填写日期与血压值后更新趋势数据。

对应页面：健康档案页。

**建议前端发送**

- 患者 ID；
- 当前会话 ID，若需要突出本轮记录。

**建议后端返回**

- 患者基本信息；
- 血压记录列表，包含日期、收缩压和舒张压；
- 历史问诊列表，包含记录 ID、时间和摘要；
- 下一次随访时间；
- 随访状态。

**录入血压时建议前端发送**

- 患者 ID；
- 测量日期；
- 收缩压；
- 舒张压。

**录入血压时建议后端返回**

- 保存成功状态；
- 更新后的血压趋势数据。

### 10. 随访提醒

对于需要继续观察的咨询结果，用户可以查看下一次随访时间和随访内容。

对应页面：健康档案页。

**建议前端发送**

- 患者 ID；
- 会话 ID。

**建议后端返回**

- 下次随访时间；
- 随访内容说明；
- 随访状态：待随访或已完成。

### 11. 重新演示

用户可以清空当前演示状态，返回首页并重新开始完整咨询流程。

对应页面：纠偏与评估页、健康档案页。

**建议前端处理**

- 清空当前前端状态；
- 返回首页；
- 重新开始时使用新的模拟数据。

**如后端保留演示会话，建议后端返回**

- 清空或结束会话的状态。

### 12. 加载与异常提示

页面需要显示请求中、信息不足、请求失败和流式输出中断等状态。

错误发生后保留用户已经填写的内容，并允许重试。

对应页面：全部页面。

**前端自行处理**

- 请求中显示加载状态；
- 防止重复提交；
- 保存用户输入；
- 显示错误提示；
- 提供重试；
- 流式中断时保留已经显示的内容。

**如采用 SSE，建议后端提供**

- 开始事件；
- 正在输出事件；
- 内容事件；
- 完成事件；
- 异常中断事件。

不要求后端返回一个“请求进行中”的普通响应，加载状态由前端根据请求和 SSE 连接状态维护。

## 待与 Agent 侧确认的字段

1. 纠偏效果指标具体包含哪几项，能否全部产出；
2. 分诊结果中“可能相关情况”和“证据来源”的最终字段结构；
3. 澄清追问最多支持几轮，是否有上限；
4. 血压趋势数据来源：用户手动录入、问诊过程中自动提取，还是两者都支持；
5. Agent 是否返回“是否需要纠偏”和实际采用的纠偏策略；
6. 原始回答和纠偏后回答是否都允许展示给用户；
7. 分诊结果中的就医层级是否使用固定枚举。
