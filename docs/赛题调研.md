# 赛题调研

第十一届华为 ICT 大赛中国创新赛赛题2。这一份记录赛题要求、评审规则和平台能力边界，用来写材料和对付答辩里的细节提问。

采集于 2026-11-18。原始取证物在同工作区的 `huawei-talent/`：`page1.txt` 是报名页全文快照，`docs/raw/` 有四十多篇 AgentArts 官方文档正文，`docs/menu.html` 是文档全目录（627 条）。下面每条平台事实都标了出处文件，可以直接倒查原文。

## 赛题要求

题目是"基于华为云 AgentArts 智能体开发平台的 Agent 设计和应用"。应用领域不限，官方举了四个方向：行业赋能型（医疗、教育、金融、制造、农业）、效率提升型（办公自动化、智能客服、数据分析、文档处理）、创新探索型（多 Agent 协同、自主决策、MCP 工具调用、持续学习）、生活服务型（健康管理、出行规划、学习辅助、智能家居）。

任务要求四条。基于 AgentArts 完成智能体的构建、编排与部署；通过可视化 Demo 页面展示核心功能和交互流程；体现 AgentArts 在智能体设计、工具编排、知识接入、多 Agent 协作、效果评估上的使用价值；形成"场景识别到 Agent 架构设计、技能编排、调试优化、部署上线"的完整闭环。这四条对着的就是评分点。

入围中国总决赛和全球总决赛的作品要在华为云开发者社区或其他社媒发布分享帖，内容建议包含 Agent 设计方案说明、知识库或语料的构建方法、自定义 Skill 或 MCP 服务说明、使用文档、Demo 截图或视频链接。

官方还发过一篇赛题二解读（华为 ICT 人才培养号，2026-11-04），里面有三条报名页没写的信息：作品须团队原创，不得基于第三方开源项目二次开发，也不得对现有项目简单包装；架构不强制多智能体，单智能体、工作流、多智能体按需选；决赛答辩跑真系统，不放录屏。

## 评审规则

初赛 2026 年 12 月。交作品信息收集表 Word（模板1），另有 PPT、设计文件、演示视频可选。内容要求包含作品简介与创意点、团队介绍、Agent 设计方案（场景定义、编排思路、工作流架构、模型与资产选择）、面向的行业问题和落地场景、基于 AgentArts 构建运行的 Demo 视频。初赛不要求 Demo 链接。评分是创新性 60% 加应用价值 40%。创新性看场景创新、与现有方案的差异化、智能体设计思路或交互方式的创新；应用价值看需求是否真实、有没有商用落地潜力、可复制和规模化前景、架构是否合理可行。

中国总决赛 2027 年 3 月，线上集中答辩，15 分钟展示加 5 分钟问答。要交答辩 PPT（模板2）、可在线访问和交互的 Demo 页面地址、Agent 设计方案文档（场景定义、编排思路、工作流架构、知识库构建方法、模型与资产选择）、自定义 Skill 或 MCP 服务说明（如有）、社区分享帖截图。最终分数 100% 由答辩当天评委组评议给出。评分是创新性 40%、应用价值 35%、完整性与可展示性 15%、答辩表现 10%。完整性那一项原文写着"基于 AgentArts 的开发流程展示完整"。

全球总决赛 2027 年 5 月深圳现场，材料同比再加上作品应用及落地进展说明、社区分享帖截图和反馈数据。评分是创新性 40%、应用价值 30%、完整性 15%、落地进展 10%、答辩 5%。

中国区队伍中英文答辩都可以，用英文答辩总分加 2 分，总分不超过 100。

三道赛题独立评审，共 54 支队伍进中国总决赛，每道 18 支。中国总决赛各赛题一等奖 4 个、二等奖 6 个、三等奖 8 个。每所学校在同一赛题最多一支队伍进全球总决赛。

## 参赛须知里的硬约束

三人学生加一名指导教师，学生和指导教师必须同校，报名截止后不能换人。实践赛、编程赛、创新赛、挑战赛报名互斥，每人只能报一个赛道。未采用赛题要求的华为技术不符合参赛资格。材料逾期未交视为弃赛。提交的代码等材料如果无法复现答辩 PPT 的效果，取消晋级和获奖资格。禁止把其他赛事作品不加改进拿来参赛。知识产权归参赛者，但授予组委会无偿复制、发行、展览、教学和网络传播的权利。

## 平台能做什么

AgentArts 有四条开发路径。Managed Agents 是全托管，你只配模型、提示词、工具，平台负责建和跑。运行时托管是自己打包容器镜像，平台提供运行环境、弹性和隔离，兼容 LangChain、LangGraph 和自研框架。低代码编排是在画布上搭单智能体、工作流或多智能体。第四条是从资产广场的应用模板改。

低码的三种类型分工不一样。单智能体是一个模型加提示词，挂插件、工作流、MCP、知识库、记忆和对话体验，适合对话、知识问答、工具调用。工作流是拖节点，节点类型包括开始、结束、大模型、判断、代码、循环、意图识别、插件、MCP、HTTP 请求、消息、输入、提问器、问答、异常、变量赋值、变量聚合、知识检索和子工作流，适合步骤明确、要求高准确率的流程。多智能体是中央控制器用模型做意图分类再路由到子智能体，支持两层嵌套，中央控制器只负责指路，子智能体直接回复用户。子智能体可以直接绑已发布的工作流，包括起始、默认和结束工作流。

官方还给了六种工作流编排范式，写"工作流架构"这一节时可以直接用这套术语：顺序链式执行、条件路由执行、并行聚合执行、循环迭代执行、嵌套编排执行、反思精炼循环。

能力面上，模型深度对接 MaaS，预置 DeepSeek 等，也支持自定义和 OpenAI 协议模型，可配模型路由。提示词有模板、智能添加和版本管理。Skill 是按文件夹规范组织的技能包（SKILL.md 加 scripts 和 references），按需加载。插件基于 OpenAPI 或 HTTP 封装任意 API，内置插件开箱即用，支持 JSON 导入。MCP 有平台精选、自定义接入和空白创建三种来源，只配服务地址就能自动发现工具。知识库是内置 RAG，召回支持语义、关键词、混合和 FAQ 四种，可调相关度阈值、topK 和 FAQ 直出阈值，有命中测试，支持按文档标签过滤检索范围。记忆是变量。对话体验有开场白、推荐问题、追问、引用和归属、内容审核。触发器具定时和周期两种。发布可以是 API 服务、网页应用或上架云商店。

观测侧有调用链 Trace、应用业务运营三类指标、日志、会话分析和异常告警，第三方智能体可以用 OpenAPI 或 SDK 上报。评估侧有离线评估和在线评估两种，预置六十多种评估器，从正确性、任务完成度、轨迹质量、工具参数正确性，到幻觉现象、引用相关性、格式检查、Token 效率、隐私泄露，也支持自定义的模型判定和自适应判定。评测集可以人工造、AI 合成，也可以从 Trace 回流。优化侧有轨迹分析、一键智能优化、工具优化、Skill 优化和模型优化。

## 十四条硬事实

这些是架构决策的依据，全部核实自官方文档原文。

| 事实 | 原文要点 | 出处 |
|---|---|---|
| 运行时镜像必须 ARM64 | "使用X86系统制作的镜像在调用智能体运行时会调用失败"，推荐 Ubuntu 22.04 ARM64 | `rt_quickstart` |
| 运行时容器契约 | 监听 0.0.0.0:8080，`POST /invocations` JSON 进 JSON 或 SSE 出，`/ws` 可选，`/ping` 健康检查不通过则实例不断重启 | `rt_inbound_http`、`rt_image` |
| 运行时无调用链和指标 | "托管智能体的调用链与指标查看功能正在规划中，暂未开放"，只有 LTS 日志 | `ops_rt_report`、`ops_rt_view` |
| 运行时路由配置 | 平台先剥掉 `/runtimes/<名>/invocations/` 前缀再转发，选"严格匹配"会 404，必须选前缀配置 | `rt_quickstart` |
| 调 API 不能用免费 token | "调用智能体/工作流API时不支持使用平台赠送的免费token"，否则返回 Model call failed | `bp_api_agent` |
| 平台调用接口是 SSE | 事件类型有 workflow_started、node_started、node_finished、node_wait、workflow_node_message、message、workflow_finished、exception、error、end | `api_events` |
| 代码节点禁止联网 | 禁用 requests、urllib、httpx、aiohttp、socket，只支持 Python 3.9 标准库子集加 numpy，禁 eval/exec/\_\_import\_\_，无文件系统，超时上限 900 秒 | `lc_node_code` |
| 低码的记忆就是变量 | 每个应用最多 30 个变量，默认值最长 500 字符，真正的记忆库要接运行时 SDK | `lc_mem`、`hc_mem_integrate` |
| 触发器不区分用户 | 周期或间隔触发，只让某个应用按一句自然语言提示跑一次会话，没有送达渠道 | `lc_trigger_app` |
| 知识检索输出没有 chunk_id | 固定输出 output_list，含文件名、子标题、分片内容、匹配分数，官方建议 topk 取 3 到 5 | `lc_node_kb` |
| 可以导出导入 jsonl | 单智能体、工作流、多智能体都支持 jsonl 导出导入，工作流还支持导入 Dify DSL | `lc_manage`、`lc_manage_wf`、`lc_manage_multi` |
| 知识库限额 | 体验版 5 个库，单库 500 文档，单智能体或单工作流最多挂 1 个 | `hc_kb_limit` |
| 订阅限制 | 体验版免费，20CU、1GB 知识库、2 名成员、50 个应用；团队版和企业版未开放，需提工单 | `pd_plan` |
| 工作流限制 | 总超时 15 分钟，插件和 HTTP 节点 50 秒，模型 15 分钟，循环最多 1000 次，非游离节点最多 150 个，查询最多 10 万字符 | `lc_wf_limit` |

另外两条用得上的：HTTP 请求节点只支持 API Key 鉴权，插件才支持 API Key 和 OAuth；知识库可以接第三方，支持 General、RAGFlow 和 KooSearch。

## 两份模板的结构

模板1 是作品信息收集表，四页，封面一页加表格三页，没有页眉页脚也没有批注。表格要填学校名称、队伍名称、指导老师（1 人）、队员姓名（不超过 3 人）、队长电话和邮箱、团队合照（1 张约 2M）。作品部分里，赛题已经写死，作品名称自己填。应用领域和应用技术这两行现在是灰色斜体的提示文字，是从赛题要求抄过来的，必须替换成作品的实际内容。作品介绍只有一条要求，写方案的背景和价值、应用场景、解决了什么问题，限 500 字。技术方案介绍分两段，第一段写 Agent 设计方案说明、知识库或语料的构建方法、自定义 Skill 或 MCP 说明、使用文档和操作指引、Demo 截图或视频链接；第二段写最终效果，要求给可量化指标。作品展示那一栏是给入围中国总决赛的社区分享帖用的。

模板2 是答辩 PPT，四页，第一页封面，后三页是空白的华为主题背景（HUAWEI logo 加 I.C. The Future），16:9。封面只有一个文本框，三行，赛题名和赛题全称不用动，第三行把"学校+队名+作品名"替换掉。九点九兆的体积全是背景图。这个模板不提供任何版式或章节提示，页面结构得自己按评审维度搭，四页显然不够，要复制母版页新增。

## 可以参考的对标

企业案例有三个。温氏食品用四个智能体串起群体基因组学分析、基因挖掘、遗传评估、育种决策，基因组分析效率提升 50%，长期记忆的 AI 解读成功率 95%，遗传评估准确率提升 15%。慧通差旅做 Agent 角色一键设定，代码量降低 90%，工作流搭建速度提升 3 倍，调试效率提升 80%。太平洋保险做保险数字员工，服务满意度 80.5%。

官方最佳实践里有一批可以直接照搬骨架的：智能客服、知识问答工作流、茶叶销售多智能体、手机银行助手多智能体（含天眼查 MCP）、辅助批改作业、智能助教、病历生成助手、全能出行助手（集成了模型、记忆、代码解释器、网关和高德 MCP），另有 RAG 优化三篇和评估三篇。学范式可以，照搬业务会踩"不得基于第三方项目二次开发"的红线。

同赛道的公开作品值得看两个。一个是「衡镜：劳动问答与仲裁助手」，15 个节点 16 条边，4 个模型角色，两级分岔，法条库走 MCP；它的分工判据是"一行代码能判对错的交给代码，其余交给模型"，法条 39 部 1719 条按来源分级，逐字可引 1671 条，引用过五道硬闸（法名存在、条号存在、施行日期、引文逐字一致、条号必须来自本轮检索池），金额必须在计算回执里找得到，缺参数就写"待算"，回复走 SSE 逐字输出。另一个是「AQIA 工业质检多智能体系统」，五智能体协作、证据约束裁决、MCP 工具与判据版本影响分析，GitCode 上有代码。
