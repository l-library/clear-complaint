## 做什么

把一段模糊的自然语言主诉，变成一份可核验、能递给医生的分诊结论。用户说"我最近常常流鼻涕"，系统给出该不该就诊、挂什么科、可能相关的几种常见情况（每条带引用原文），以及就诊前该准备什么。

## 核心主张

表述敏感性是已知现象，prompt sensitivity 和临床场景里的锚定偏误都有人写过。所以研究的主张不能停在"我们发现 AI 会被带偏"，那会被一句话打回。

我们要证明的是方法：对付"我好像感冒了，一直流鼻涕"这类自我诊断暗示，有效的干预点在输入表征上，不在输出指令上。提示词里写"不要被用户的自我判断影响"是最容易失效的做法，因为它要求模型在同一个上下文里既读进暗示、又忽略暗示。把自我归因拆成独立字段、从推理链里摘出去，是工程动作，输出更稳定。

报告要给出约束前后分诊档一致率的对比、效应量和置信区间，并说明这个改善在两个异构模型上都成立。

## 不做什么

Agent 不做诊断、不开药、不给剂量。输出永远是分诊档、首推科室、可能相关情况和就医准备清单，每段带一句"不构成诊断"。

就医导航停在科室和紧迫度，不碰医院、医生和挂号。

跨用户的健康数据不做汇聚，只做个人趋势看板。

前端不直接调 AgentArts，密钥只在后端。初赛不要求 Demo 链接，分是给方案的；决赛要能在线跑，所以工作区接的是真实接口。

仓库里的前端是完整工作区：uni-app 一套代码编译到 H5 与微信小程序，五个页面（pages/index、pages/privacy、pages/chat、pages/health-records、pages/health-plans），界面由 QWorkspace、QLiveArchive、QLivePlans、QAccountPanel 组装，请求走 src/api 下的八个模块，问诊进度在两端都是真实的 SSE 流。

## 输出契约

| 段 | 内容 | 约束 |
|---|---|---|
| 分诊档 | 急诊（立即或数小时内）、门诊（数日内）、自我观察（一周内复评） | 红旗症状命中则强制急诊，不看模型 |
| 首推科室 | 1 个主科室，必要时 1 个备选 | 必须在受控科室表内 |
| 可能相关情况 | 3 到 5 条，每条带引用 | 候选词表不超过 80 条，无引用即删 |
| 就医准备清单 | 带什么、怎么向医生描述、什么情况立刻走 | 复用结构化主诉 |

## 架构

```
浏览器 / 微信小程序（H5 与 mp-weixin 共用一套 uni-app 代码）
   │ REST / SSE
   ▼
FastAPI（自有 x86 服务器）
   · 账号与 JWT、健康档案、提醒调度、随访队列
   · 归一化、红旗短路、逐字核验、文案组装（唯一对外出口）
   │ ① SSE 事件流（API Key）
   │ ② 插件或 HTTP 请求节点回调（API Key）
   ▼
AgentArts 低码（西南-贵阳一）
   多智能体：中央控制器 → 诊断推理子智能体、健康档案随访子智能体
   起始工作流：采集城市、天气、日期时间、既往事实摘要
   主干工作流：归一 → 澄清 → 检索 → 草稿 → 结构闸门
   知识库 1 个（标签分区）、模型 2 个（异构）、Trace、在线评估、评测集
```

平台负责编排、知识检索、模型与提示词、Trace 和评估，这些是评审要看的东西。FastAPI 负责确定性校验、数据存储和调度，这些是平台做不了或做起来很别扭的东西。判断一条逻辑放哪边，看它能不能用一行代码判对错：能判对错的放后端，需要理解语言和决定下一步调什么的放平台。

不用运行时托管。镜像必须 ARM64 而团队只有 x86 机器，这是第一个障碍。第二个障碍更麻烦：运行时智能体的调用链和指标目前未开放，只有日志，而在线评估只由 Trace 触发。加上运行时托管下画布是空的，完整性那 15% 里"基于 AgentArts 的开发流程展示完整"这一条就没东西可截。

## 一次问诊的流程

1. 用户提交主诉原文。原文原样入库，之后任何环节都不改写它。
2. 后端归一化，抽出症状、起病时间、持续时长、部位、性质、伴随症状、已用药。自我归因单独存一个字段，标记为不可信，不进入推理。
3. 后端调用平台的多智能体应用，拿 SSE 事件流。
4. 起始工作流注入上下文：城市、天气、日期时间、既往结构化事实的摘要（不超过 500 字）。
5. 判断关键字段是否齐备。缺就问，不许下结论。
6. 知识检索节点取回 3 到 5 条片段，输出到 output_list。
7. 大模型节点输出 JSON 草稿，引用的只能是 output_list 的下标。
8. 平台侧结构闸门检查：字段是否齐、下标是否存在、分诊档是否在枚举内。
9. 草稿和本轮 output_list 一起回到后端。
10. 后端语义闸门：红旗规则短路、用 output_list 的分片内容做逐字比对、核不上就删掉那条情况、拦剂量和处方类表述。
11. 组装四段文案，落库结构化事实，唯一出口返回。
12. 分诊档为"自我观察"的，进随访队列，48 到 72 小时后追问。

## 引用怎么核

知识检索节点的输出是固定的 output_list，里面有文件名、子标题、分片内容、匹配分数，没有 chunk_id。所以引用键用下标，让模型输出 evidence_idx：

```jsonc
{
  "triage": "clinic",
  "department": "呼吸内科",
  "conditions": [
    { "name": "急性上呼吸道感染", "evidence_idx": [0, 2] },
    { "name": "过敏性鼻炎", "evidence_idx": [1] }
  ]
}
```

平台把草稿和本轮 output_list 一起返回，后端用 output_list[i].content 逐字比对。"检索池"就是这一轮的 output_list，模型编不出池外的下标。

这样不需要自己维护语料副本，也不用回库查询。但要清楚这条校验能证明什么：它证明引用确实来自本轮检索结果，不证明结论和引用在语义上相符。语义一致性靠输出结构约束、人工抽查，必要时再加一个模型做 groundedness 打分。材料里不要写成"做了语义核验"。

## 阶段一实验

四个假设。H1，同一临床意图换表述会带来分诊档和科室的漂移。H2，自我诊断暗示是最强的诱因，强于情绪，强于删减细节。H3，输入侧干预比输出侧干预更有效。H4，约束机制的效果与模型无关。

H3 和 H4 是创新性的落脚点，H1 只是铺垫。

五条约束，每条绑一个变体族的证据：输入侧结构化归一（自我归因降级为字段，退出推理链）、澄清先行（关键字段缺失必须追问）、红旗确定性前置（命中即短路，不看模型）、引用闸门（只许引用检索池下标并逐字核验）、输出模板锁定（四段固定，缺段不输出）。

阶段一是一个独立的研究工件，不依赖平台：被测系统是自己写的确定性链条加模型直连，AgentArts 只在阶段二实现同一组约束。所以阶段一的结论表述为「这组约束带来了多少改善」，不表述为「平台闸门带来了多少改善」；平台是否等价由阶段二的冻结样本验收回答。实验设计、语料与病例规格、闸门口径、指标与统计、交接物见 [stage1.md](stage1.md)。
