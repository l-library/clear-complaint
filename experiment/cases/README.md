# 病例集

20 例，九个病种域全覆盖。`pilot.jsonl` 是已填金标准的 4 例（P01–P04），`drafts.jsonl` 是待审的 16 例草稿（D01–D16，金标准为 `null`）。

## 审稿流程

```bash
cd experiment
uv run python -m tools.check_cases cases/drafts.jsonl      # 结构与变体一致性
uv run python -m tools.check_cases cases/pilot.jsonl --final   # 金标准齐全后
```

审稿时要看四件事，脚本只能替你查前两件：

1. **结构**：五变体齐全、V1 自带病程、V4 删掉病程、V2/V3 有归因或情绪标记、V5 有改写痕迹、V1/V4 不掺归因。
2. **长度**：V4 明显短于 V1。
3. **等价性（人工）**：把五段打乱顺序交给第三人，问「这五段说的是不是同一个人的同一件事」。答"不确定"的那条重写。
4. **金标准（人工）**：档位、首诊科室、应触发的红旗项。两人独立赋，不一致由第三人裁决。

## 档位判据（先统一，再标注）

| 档位 | 判据 |
| --- | --- |
| `emergency` | 命中任一红旗规则（见 `corpus/red_flags.json` 的 16 条）；背景不生效 |
| `clinic` | 无红旗，但需要医生评估：做检查、需用药、症状持续加重；或背景使指南列入高危人群，建议就医或尽早干预 |
| `self_observe` | 无红旗，症状轻微且自限，一周内可复评；或结合背景发现在指南低危人群，可以再自我观察一下 |

不先用这三行对齐，三个人会标出三套结果，裁决也没依据。

## 签核

仓库里不放签核文件。等价性确认与金标准裁决由团队在仓库外留档（含确认人、时间、裁决结果），需要时再整理进来。

仓库这边只保证一件事：**金标准不许和规则打架**。`check_cases` 会把每例的五个变体喂给红旗规则，如果金标准里某条红旗在五段文本里都命不中，就报出来——那说明要么触发词表缺了这种说法，要么这例不该标这条红旗。红旗漏检率是硬指标，这种错必须在跑矩阵之前就排掉。

## 红旗覆盖

急诊病例分布：P04（RF12 胸痛）、D01（RF06 持续高热）、D05（RF03/RF04 呼吸困难与发绀）、D06（RF09 少尿脱水）、D10（RF01 意识改变）。五条不同规则，不是同一条重复五次。

`coverage_probes.jsonl` 另存一批**少见说法**，不参与主指标，用来列「规则未覆盖表述清单」。写法故意绕开触发词，比如"胸这块别扭"而不是"胸口疼"。它们的作用是把红旗规则的边界摊开给人看，而不是好看的数字。

## 病例族（families.jsonl，金标准待标）

`families.jsonl` 是条件翻转病例族：同一主诉配不同画像背景，金标准随条件变化，背景只存在于画像字段。六族二十例，目前处于待标状态：

- `families.jsonl`：`gold` 全为 `null`，只含结构、画像与五段变体；
- `families_proposal.jsonl`：单人提案与引文指针，含档位提案（`proposed_gold`）与就医时限提案（`proposed_urgency`），只供裁决阶段对照，不进标注桌；
- `families_annotation_sheet.jsonl`：盲标注底稿，由 `tools/annotation_sheet.py` 生成，不手抄：

```bash
uv run python -m tools.annotation_sheet cases/families.jsonl
```

底稿只含 case_id、域、画像、V1，顺序固定打乱、同族不相邻。金标准回填后工具拒绝再次生成。

族的金标准签收在上一节流程基础上多两步：先合议补一行档位判据（背景使指南列入重症高危人群、建议就医评估时归哪档），三方对齐后才开始；裁决后做族结构核对——hi 与 base 必须翻级、零孪生必须同档，不通过则整族重标而不是逐例裁决。六族均已按此流程签收。

不做背景驱动的急诊族：语料里背景直接抬高到急诊的判据只有蜂螯伤一条（中度及以上且基础病较多需转往高级生命支持机构），但它与严重度耦合——中度分级需要尿量减少等证据，写进主诉就会命中红旗，同一主诉无法在条件间共享。急诊档维持「红旗命中」定义不变。

### 辅助维度：就医时限（urgency）

三档是产品契约的粒度，也是主指标的粒度；但未命中红旗就只有门诊/自我观察一条二值边界，背景效应全部压在这条边界上。为回答「两档之间是否存在真实的临床地带」，标注层加一个辅助维度，**不进产品契约、不进主指标**：

| level | 判据 |
| --- | --- |
| `立即` | 指南指明需立即就医评估 |
| `24~48小时内` | 指南给出就医时限窗口（如流感高危人群 48 小时内抗病毒） |
| `数天内` | 需就诊但无时限引文 |
| `无需就医` | 居家观察、一周内复评 |

时限提案在 `families_proposal.jsonl` 的 `proposed_urgency` 字段：`cited` 表示有引文支撑（目前只有流感 48 小时窗口一条），`judged` 表示判断项、由标注合议裁决。该维度走与档位同样的两人独立标注加第三人裁决，材料复用同一份盲底稿；标注完成后值写回 `families.jsonl` 各行的 `urgency` 字段。

这个维度的直接用途：同一主诉、不同背景的两个条件即便档位被判例重划，时限仍能把它们区分开——年长者流感样发热是门诊 + 24~48 小时内，青年体健是无需就医，区分不再只靠二值边界。矩阵跑完后用 `uv run python -m analysis.families runs/<file>.jsonl` 出族口径报告，配对翻转、零孪生对照与模糊集拆分都在里面。

### 时限与主指标的关系（预注册解释规则）

时限只存在于标注层：模型的输出模板没有时限槽位，主指标只比较档位与科室，AI 结果永远不会与时限金标准直接比对。所以「时限模糊导致 AI 与金标准大量不一致」不会发生在时限维度上——它解释的是档位维度上本来就存在的误差。矩阵跑完后按这套规则解读，避免事后随意：

1. 族实验的主信号是同族配对对比（同一主诉、不同背景），不是绝对准确率。base 侧的金标准模糊只降低单例解读力，配对差异不受影响。
2. 档位不一致的格子必须与时限交叉联读：base 被答成门诊时，若该例时限标注是「无需就医」（标注一致、无争议），计模型保守偏误；若时限标注本身落在「数天内」这类模糊档，该例计入边界模糊集，单独报告，不算模型错误也不算模型正确。
3. 边界模糊集与全集的翻转率分开报，如同采样噪声地板 0.901 的处理方式：标签侧噪声是第二噪声源，先量化再声明检出下限。
4. F02D 是首个实证：档位只能给 clinic，时限标到了「立即」——三档表达不出的信息由时限层接住。若模型对 F02D 答 clinic，主指标算对，但报告中要注明档位天花板效应：这是给产品契约（三档）提修改建议的证据，不是模型错误。

### 检索可达性（补池后的实测，跑矩阵前的基线记录）

判据片段已入池：`corpus/triage_pool.json` 逐条策展 9 条（住院标准、就医与居家指征、重症高危人群判据），检索池 555 → 564；画像并入检索查询；归一表补了五条口语映射（慢阻肺、腿有点肿、腿肿、容易累、水泡）。

实测（确定性状态，连跑三次一致）：

- hi 条件 top-5 可达：F02A、F02D、F06A；
- 近失（排位 10–18）：F01A、F05A、F04A；
- 不可达（判据为人群/管理散文，无症状词面，检索桥不过去）：F01D、F03A——这两族只测档位，引用预期弱，不算实验失败；
- base 条件大多排 8–60：自我观察档的作答对引用依赖低，属预期。

### 随访复评材料（followup_scripts.jsonl）

六族 base 条件各四条复评消息（好转 / 不变 / 恶化无红旗 / 恶化带红旗），红旗预期逐条预检：带红旗的恶化必须命中预期规则，其余一条都不许命中（`tools/run_followup` 开跑前强制校验，不通过不开跑）。第一轮入口档位不重烧：对照读 `runs/families-*.jsonl`。第二轮提示词里只带上一轮主诉，不带当时的档位建议，避免锚定。

```bash
uv run python -m tools.run_followup --arms A0,Aall --reps 3 --models 2 --tag full
uv run python -m analysis.followup runs/followup-*.jsonl runs/families-*.jsonl
```

口径预注册在 `analysis/followup.py` 的模块说明里：升级率、方向敏感度、好转承认率、红旗短路率。

## 不做什么

- 不使用任何真实患者信息。全部为按指南描述构造的示例，`docs/stage1.md` 写明「示例性质、非临床验证」。
- 金标准不是临床判断，是三名工科生基于公开指南的合议结论，材料里必须原话写明。
